Build network services without limitations.

Rama® is a modular service framework for Rust that gives you programmable control over your entire network stack.

Build production-ready proxies, servers, clients, API gateways, traffic inspection tools, and custom network services using composable building blocks instead of rigid abstractions.

Why rama

Why teams build on Rama

Off-the-shelf proxies and web servers work until the network stack becomes part of your product. Rama gives you the building blocks to build exactly the stack you need, plug in your own modules, and keep every decision in code, in a language that empowers you: Rust.

for security vendors & platform teams

Own the traffic you need to secure

Security products need to see and steer traffic, often on the device itself. Rama gives you the whole stack, from transparent capture to TLS interception, as modules you compose and extend in Rust. Firewall rules, routing and setup become your code, not the config file of someone else's proxy.

  • Transparent proxies on macOS & iOS, Windows and Linux
  • TLS interception for HTTP/1.1, H2, H3 and WebSockets
  • Traffic capture and inspection, with HAR export
  • System proxy and PAC aware routing
  • XPC for app to extension IPC on Apple platforms
Explore MITM proxies →

for researchers & data teams

Look like a browser, without running one

Collecting public data at scale with headless browsers is slow and expensive. Rama clients emulate real browsers down to their TLS and HTTP fingerprints, rotate through upstream proxies and process what comes back, all from lean async Rust.

  • HTTP and TLS emulation of real User-Agents
  • HTTP/1.1, H2 and H3 clients you control at every layer
  • Upstream proxy pools with filters and username config
  • HTML and JSON processors for what comes back
  • HAR recording and replay
Read about UA emulation →

for teams running their own services

Run your edge, end to end

Serve your services from the socket to the response, with security you control at every layer: certificates, client fingerprints and bot defence included. Keep a PHP app running behind the same binary, as the only backend or as a fallback while you migrate.

  • TLS with certificates issued through ACME
  • JA3, JA4, JA4H and Akamai H2 fingerprints of every client
  • Anti-bot answers such as infinite resources and zip bombs
  • PHP and other FastCGI apps as backend or fallback router
  • Web services over HTTP/1.1, H2 and H3

Two ways to use rama

Get Started with Rama

Choose your preferred installation method. Either add Rama as a framework dependency to your Rust project for maximum flexibility and control, or install the pre-built Rama CLI binary for immediate use as a standalone tool without writing code.

As a framework library

Use Rama as the foundation of your own codebase. Add it as a dependency to your Rust project:

Then start from an example that does something real:

  • MITM proxy with browser emulation Terminates TLS and sends traffic upstream as a captured browser profile, chosen per client. →
  • HTTP/3 interception Peeks each QUIC ClientHello, terminates HTTP/3 for chosen hosts and forwards the rest untouched. →
  • MASQUE CONNECT-UDP proxy HTTP/3 through CONNECT-UDP tunnels, next to ordinary CONNECT, on one port. →
  • TLS SNI router Routes TLS connections by server name with BoringSSL. →
  • ICAP adaptation proxy HTTP(S) MITM proxy with embedded or external ICAP response adaptation. →
Browse all 100+ examples →

As a CLI binary

Run the Rama CLI for traffic inspection, intelligence gathering, tunneling, and network diagnostics, without writing any code.

Install Rama CLI using curl, or from source:

terminal
# HTTP client for HTTP/1.1, H2 and H3, with curl-like flags
$ rama https://ramaproxy.org

# emulate a browser with the embedded User-Agent profiles
$ rama send --emulate https://example.com

# HTTP + SOCKS5 proxy with a traffic inspection web UI
$ rama serve proxy --mitm

# resolve DNS records, open a WebSocket, probe TLS, ...
$ rama resolve ramaproxy.org HTTPS
$ rama wss://echo.ramaproxy.org

How it works

Built for Modularity

Rama is built around a service model where services are fallible async methods that can be stacked, branched, and composed. You can wire together transport, TLS, HTTP, proxy logic, and telemetry as a set of reusable building blocks instead of a single large framework.

  • Flexible middleware layers and service composition
  • Custom service implementations using your preferred Rust libraries or custom code
  • Easy integration with existing crates, tools, and infrastructure

Bring your own stack

You can keep using your existing HTTP or TLS stack, such as curl or OpenSSL, and attach Rama only where you need it. Or you can start from the built in Rama services and swap out parts of the stack as your needs grow.

For developers and organisations

If you are a developer, you get a composable toolkit for building proxies, servers, and clients that fit your codebase. If you are an organisation, you can treat Rama as a platform component and rely on our professional services for design, integration, and long term maintenance.

Minimal by design

Our built in services are intentionally minimal, which makes them easy to extend or modify. The entire codebase is open for you to use as inspiration, adapt to your own environment, or harden for production workloads.
